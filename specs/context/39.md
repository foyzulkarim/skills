# Task 39: feat(plan-qa, execute-qa): environments, qa-browser driver, lanes, bug mode, visual judgment, and traceability check

- **Type:** feat
- **Source:** GitHub issue #39
- **State:** OPEN
- **Labels:** enhancement
- **Created:** 2026-08-31

## Description

## Summary

Upgrade the QA pair (`/plan-qa` + `/execute-qa`) from a local-only, serial, DOM-assert-only workflow into an environment-portable, parallelizable one with a real persistent browser driver and a bug-repro mode — and add a requirements-traceability check to the review phase so coverage claims are verified, not assumed.

## Motivation

Today QA plans hardcode `localhost`, `[browser]` steps lean on ad-hoc Playwright calls with no session persistence, runs are strictly serial, rendering bugs have no verification tier, a bug fix has no dedicated planning path, and nothing mechanically checks that every REQ-ID is actually covered by a test or QA case. These changes close all six gaps.

## Changes

### plan-qa
- **Bug mode** — third entry mode (`/plan-qa bug #123`): one short repro interview, plan = the repro case (asserting the *fixed* behavior) + regression smoke over the Coverage Map.
- **Environment portability** — relative URLs only (`goto /settings`), `[bash local-only]` tagging with remote-equivalent Guards, logical identities with credentials from the run env file.
- **Lanes** — parallelism decided at plan time: collision rules (shared identity, mutable state, throttles, resets), lane-1 pinned for operator handoffs and log correlation, Readiness Gate line enforcing lane isolation.
- **`[judge-visual]` tier** — screenshot-based judgment with a written pass/fail criterion and optional design reference.

### execute-qa
- **Environments** — `--env <name>` / `--base <url>` flags, gitignored `.env.qa.<name>` files, production guard, local-only steps → SKIPPED with reason on remote bases.
- **Browser Driver** — new bundled `qa-browser.mjs`: persistent headed Playwright daemon, one JSON line + exit code per command, step→command mapping, per-identity contexts, `env:NAME` secret substitution, auto-screenshot on failure, log-correlation pattern.
- **Lane execution** — one subagent per lane with `--ctx <lane>` routing (isolated cookies/storage + console/network buffers per lane); parent merges into QA-RESULTS.
- **`[judge-visual]` verdicts** — judged from the captured screenshot; missing screenshot is a structural plan error.

### review
- **New 17th sub-check `requirements-traceability.md`** (pipeline mode only):
  - Mechanical pass: every REQ-ID appears in ≥1 QA case `Req` column, automated test, or TASKS verification plan (orphan → UNCOVERED finding); every changed file traces to ≥1 REQ-ID via specs or the QA Coverage Map (untraceable → possible scope creep).
  - Semantic pass: per acceptance criterion, verdict VERIFIED / WEAK / UNCOVERED with verbatim quoted evidence — never coverage asserted from memory.

### housekeeping
- Remove `execute-qa/skill-additions.md` (authoring scratch file; all three sections are applied by this change).

## Notes

- Per repo convention, version bumps (`plugin.json` + `marketplace.json`) ship with the PR.
- `review` currently dispatches 16 checks; its SKILL.md and `_protocol.md` references to the check count need updating to 17.

## Acceptance criteria

## Code review: `qa-browser.mjs` (execute-qa driver)

Reviewed `dev-pipeline/skills/execute-qa/qa-browser.mjs` as executed by AI agents (plan-qa / execute-qa). Overall design is solid — daemon + one-JSON-line-per-command is exactly right for agent-driven browsing, and headed-default / `--ctx` lanes / `env:` secret substitution / auto-screenshot-on-failure are all agent-friendly choices. Improvement scope below, ordered by impact. **No code changed.**

### Correctness / robustness

1. **No command duration guard.** The HTTP handler has try/catch but no timeout; `goto` (default nav timeout), a never-resolving `eval` promise, or a hung `page.screenshot` blocks the single server indefinitely. The agent waits forever with no diagnostic.
2. **Lanes imply concurrency, but the server shares a `current` global.** Two simultaneous requests with different `--ctx` values interleave while request bodies stream in — `current` can be cross-wired between lanes, mis-routing commands and auto-shot attribution. Either serialize with a mutex/queue or soften the "safe for concurrent subagents" claim in the header.
3. **`new-context` leaks the old context.** `contexts.delete(name)` drops the map entry without `ctx.close()` — repeated `new-context` calls accumulate live contexts/pages in the browser (memory + tab clutter in the headed window).
4. **`--port` is serve-only; the client ignores it.** Client always uses `QA_BROWSER_PORT` env or 8787 — serving on `--port 9000` requires also exporting `QA_BROWSER_PORT=9000`. An agent will trip on this.
5. **`assert-visible` selector-vs-text heuristic is fragile.** `/[=\[\.#>]/.test(target)` misclassifies plain text containing `.` (e.g. `"Error. Try again"` → treated as selector), and bare tag selectors like `button` get treated as text. An explicit `selector:`/`text:` prefix convention would be unambiguous for the agent.
6. **`network` ring buffer is 200 entries globally** — a filtered request may already be evicted on busy pages. Acceptable, worth a comment.

### Agent ergonomics

7. **No `wait` / `wait-for` command.** Real QA flows constantly need "wait for selector/text/network idle"; today the agent must poll via `eval` or retry `assert-visible`. A `wait-for` (Playwright `waitFor`) + maybe `wait-idle` would eliminate the most common flaky failure mode.
8. **`fill` echo inconsistency:** returns `env:NAME` for env refs but `(literal)` for literals — harmless secret-wise, just inconsistent.
9. **No `type` command** (only `fill`, which clears first) — keyboard-driven flows sometimes need per-character typing.
10. **No health/status command.** `stop` exists, but there's no `status` (contexts, current URLs). An agent recovering from a crashed daemon must infer state from errors.
11. **`console-errors` misses uncaught exceptions** — only captures `console` type `error`; add `page.on("pageerror", ...)` — often the actual bug.
12. **Screenshot paths are daemon-CWD-relative.** `screenshot <path>` and auto-shots resolve against the daemon's CWD, not the caller's — the agent can save a file it can't find. Resolve to absolute in the daemon and return absolute paths.
13. **`eval` is a footgun but also the escape hatch** — keep, but document as last-resort.

### Minor / polish

14. `route mock` forces `contentType: application/json` — can't mock HTML/images. Fine for QA; note it.
15. No request-body size limit on the HTTP server.
16. Unknown flags to `serve` throw uncaught from `parseArgs` → cryptic startup crash; wrap with usage.
17. **`--ctx <typo>` silently creates a fresh empty context** instead of erroring (unlike `use-context`, which errors). For an AI agent, failing loudly on unknown lane names beats a silent fresh context.

### Bottom line

Ship-quality for serial single-agent use today. Fix before trusting in the pipeline: **#2** (if subagents ever run in parallel) and **#7** (absence of `wait-for` will cause the majority of flaky agent failures). **#11** is the best debuggability-per-line change.

### Comment 2 — foyzulkarim, 2026-08-30T21:39:29Z

Source: https://github.com/foyzulkarim/skills/issues/39#issuecomment-5471419419

## qa-browser.mjs improvement scope

A focused review of `dev-pipeline/skills/execute-qa/qa-browser.mjs` after the current state lands. The script's architecture is right (one daemon, many contexts, lanes, `env:` redaction, auto-screenshot) — everything below is polish on that structure. Grouped by impact.

### 1. LLM-driver ergonomics (highest leverage — this is the script's actual purpose)

- **`waitUntil: "domcontentloaded"` is wrong for SPAs** (`qa-browser.mjs:149`). Most QA targets are client-routed. `networkidle` is the safer default; slower nav is invisible to an LLM driver.
- **`eval` joins args with a single space** (`qa-browser.mjs:201`). Any JS with internal whitespace silently collapses. Either accept one quoted arg, or add a `script-file <path>` form.
- **`assert-visible` selector sniffing** (`qa-browser.mjs:170`) — the regex guess between "text" and "CSS selector" will misfire on class names containing `.` or strings like `text=Foo.bar`. Force an explicit `text=` / `css=` / `role=` prefix and drop the heuristic.
- **No `wait-for <selector>` command.** LLMs fall back to bash `sleep` loops, which is the wrong tool.
- **No way to read text or attribute value.** The script only asserts. `expect-text` / `get-attr` would let an LLM verify "the count is N" without `eval`.
- **No `count` / `all` / `nth` selector power.** Always `locator(selector).first()` (`qa-browser.mjs:154, 160, 165, 171, 176`). Ambiguous UIs need disambiguation that isn't exposed.
- **No "expect a network request was made" command.** `network` (`qa-browser.mjs:188-192`) only lists; it can't assert. `expect-request <method> <pattern> <status?>` would be high-leverage.
- **No `route list`.** `route mock` / `route clear` exist (`qa-browser.mjs:223-241`) but the agent can't introspect what's currently mocked.

### 2. Reliability / lifecycle

- **No `status` command or pid file.** The skill says "start once, stop at the end" but the agent has no deterministic way to check daemon liveness. A `status` returning `{ ok, up, contexts, pid, headed, base, port }` lets the LLM recover from a previous run's orphan.
- **No signal handlers.** `Ctrl-C` / parent death leaves the Playwright browser process orphaned.
- **`stop` has a 100ms race** (`qa-browser.mjs:242-245`) — late-arriving commands hit a server mid-teardown. Mark `stop` as final or send a `stopped` event on the response.
- **No browser-restart watchdog.** If Playwright's browser process dies, the HTTP server stays up and every command hangs. A startup `health` ping + restart policy is needed.
- **The `current` pointer is module-global** (`qa-browser.mjs:122`, mutated at `:259`, read at `:266`). Two requests in flight overwrite each other. Real race for the parallel-subagent use case the lanes are designed to support. Per-request state should live in the handler closure.

### 3. Security / secret handling

- **Literal `fill` value redaction is fine** (the LLM already knows what it typed). But there's no length/fingerprint either, so debugging "did the right value get into the field?" is impossible from the response. Add `{ length, sha256: <8 hex> }` for the literal case.
- **Threat model isn't documented.** Daemon binds `127.0.0.1` (`qa-browser.mjs:280`) — fine on a dev box, surprising in a container/CI. One-line header comment: "127.0.0.1 only; never expose beyond loopback."

### 4. API consistency

- **Response shapes are inconsistent.** `route mock` → `{ok, mocking, status}`, `route abort` → `{ok, aborting}`, `route clear` → `{ok, routes}`. `console-errors` returns `errors` but no `count`. Pick a convention: `{ok, ...}` plus optional `evidence` / `count` / `hint`.
- **No top-level `elapsedMs` or `command` echo in the response.** Hard to correlate failures to specific calls when daemon and agent logs live in different places.

### 5. Code quality (low priority, cosmetic)

- **`qa-browser.mjs:115-117` `requests.push(...) > 200 && entry.requests.shift()`** — clever-but-fragile, three side effects in one expression. Split it; also make the 200 cap env-configurable.
- **`qa-browser.mjs:84-92`** `port` is typed `string` then re-cast at `:280`; should be `default: PORT` and the cast can go.
- **No `try`/cleanup in handler dispatch.** If a handler throws synchronously somewhere unexpected, the auto-shot path runs with stale `current` state (same race as the concurrency issue).

### 6. Documentation gaps

- **Env vars are not enumerated anywhere central** — `QA_BROWSER_PORT`, `QA_BASE_URL`, `QA_STATE_DIR`, `QA_SHOT_DIR`, plus the secret `env:` resolution. SKILL.md has some, the script header has some, neither has all.
- **The startup-banner convention isn't documented for consumers** — the daemon prints one JSON line on `listen` (`qa-browser.mjs:281`). Agents parsing stdout need to know to skip the first line.
- **The `eval` whitespace limitation** is not mentioned anywhere. An LLM that hits it has no way to learn.

### 7. Optional / out of scope for this issue

- **Batch command mode** — `node qa-browser.mjs batch < file.jsonl`. 20-step cases currently spawn 20 processes. Fine today, painful at scale.
- **Health endpoint** (`/health`) for parent-process monitoring.
- **Request timing in `network`** — currently `{method, url, status}`, no duration.

### What's already right (don't touch)

One browser / many contexts, headed by default, lanes via `--ctx`, `env:NAME` redaction, auto-screenshot on failure with the `NO_AUTOSHOT` set, per-context console-error and request buffers. Those six are load-bearing.
