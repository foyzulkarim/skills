# Task 39: feat(plan-qa, execute-qa): environments, qa-browser driver, lanes, bug mode, visual judgment, and traceability check

- **Type:** feat
- **Source:** GitHub issue #39
- **State:** OPEN
- **Labels:** enhancement
- **Created:** 2026-08-31

## Description

## Summary

Upgrade the QA pair (`/plan-qa` + `/execute-qa`) from a local-only, serial, DOM-assert-only workflow into an environment-portable, parallelizable one with a real persistent browser driver and a bug-repro mode — and add a requirements-traceability check to the review phase so coverage claims are verified, not assumed.

## Motivation

Today QA plans hardcode `localhost`, `[browser]` steps lean on ad-hoc Playwright calls with no session persistence, runs are strictly serial, rendering bugs have no verification tier, a bug fix has no dedicated planning path, and nothing mechanically checks that every REQ-ID is actually covered by a test or QA case. These changes close all six gaps.

## Changes

### plan-qa
- **Bug mode** — third entry mode (`/plan-qa bug #123`): one short repro interview, plan = the repro case (asserting the *fixed* behavior) + regression smoke over the Coverage Map.
- **Environment portability** — relative URLs only (`goto /settings`), `[bash local-only]` tagging with remote-equivalent Guards, logical identities with credentials from the run env file.
- **Lanes** — parallelism decided at plan time: collision rules (shared identity, mutable state, throttles, resets), lane-1 pinned for operator handoffs and log correlation, Readiness Gate line enforcing lane isolation.
- **`[judge-visual]` tier** — screenshot-based judgment with a written pass/fail criterion and optional design reference.

### execute-qa
- **Environments** — `--env <name>` / `--base <url>` flags, gitignored `.env.qa.<name>` files, production guard, local-only steps → SKIPPED with reason on remote bases.
- **Browser Driver** — new bundled `qa-browser.mjs`: persistent headed Playwright daemon, one JSON line + exit code per command, step→command mapping, per-identity contexts, `env:NAME` secret substitution, auto-screenshot on failure, log-correlation pattern.
- **Lane execution** — one subagent per lane with `--ctx <lane>` routing (isolated cookies/storage + console/network buffers per lane); parent merges into QA-RESULTS.
- **`[judge-visual]` verdicts** — judged from the captured screenshot; missing screenshot is a structural plan error.

### review
- **New 17th sub-check `requirements-traceability.md`** (pipeline mode only):
  - Mechanical pass: every REQ-ID appears in ≥1 QA case `Req` column, automated test, or TASKS verification plan (orphan → UNCOVERED finding); every changed file traces to ≥1 REQ-ID via specs or the QA Coverage Map (untraceable → possible scope creep).
  - Semantic pass: per acceptance criterion, verdict VERIFIED / WEAK / UNCOVERED with verbatim quoted evidence — never coverage asserted from memory.

### housekeeping
- Remove `execute-qa/skill-additions.md` (authoring scratch file; all three sections are applied by this change).

## Notes

- `review` currently dispatches 16 checks; its SKILL.md and `_protocol.md` references to the check count need updating to 17.

## Acceptance criteria

- [ ] `/plan-qa bug <desc>` produces a repro + regression-smoke plan
- [ ] A plan written for `--env local` runs unchanged against `--base <staging-url>`, with local-only steps recorded SKIPPED
- [ ] `[browser]` steps execute end-to-end through `qa-browser.mjs` (serve → commands → stop)
- [ ] A multi-lane plan runs lanes in parallel subagents without evidence cross-contamination
- [ ] A `[judge-visual]` case yields a verdict with the screenshot path recorded as evidence
- [ ] `/review` on a pipeline branch runs the traceability check and flags an orphan REQ-ID as UNCOVERED
- [ ] `skill-additions.md` is removed from the tree
